# Track C: performance log

## Summary

Final: v4 (row 33). Board 49.3 ms, 12.4 MB, K 25.32, 70.17 points (run-1e5d2353fd9f); the reference is 14.44 s and 367 MB.

Decisive steps, all board runs:

1. v1: 12 threads, chunk cuts guessed and then proven by quote parity, a shared lock-free name table: 61.9 ms, 16.2 MB (run-c898fb001979; the rerun run-247c2a2868f1 was within 0.2%).
2. v2: an AVX2 bitmask parser (prefix-XOR quotes), fixed 24-byte name keys, batched prefetching, parallel start-up: 52.8 ms, 12.1 MB (run-be5f1e4a22bf); v3, code hygiene, 52.4 ms (run-d3c2badf14df).
3. Failed: owner-partitioned names, 20 to 25% faster locally but 52.2 ms on the box at S 889 (run-0caa577fd90b); reverted.
4. Probes (wrong output on purpose, so red on the board): run-1f26df4f9d6d, run-eec975c57826, run-30db742f2dea, run-16449b27e8f7, run-c09fe1629bb8. The scan costs the same on both machines; per-record work costs 2 to 3 times more on the 2.5 GHz, turbo-off box.
5. pread instead of mmap: 49.3 ms (run-2890a0259c6b); 64 KiB pieces and a 128-byte pad bring M back: 49.2 to 49.3 ms, 12.4 to 12.5 MB.

Lesson: local A/B on memory-bound changes did not transfer to the box; only measurements on the box did.

Rows with a Run ID are board measurements. Box split: scan 12.7 ms, flattening +5.2, field parsing and aggregates +12.3, region map and its start-up +1.1, names +21.1. Hyperthread pairs help on the box (6 threads: v3 71.0 ms against 52.4, and 33.5 against 31.3 without names), so the pairs sharing a core's 1.25 MB L2 are not the problem. The scan costs about the same on both machines, while the per-record work costs 2 to 3 times more on the box. The box runs at 2.5 GHz with turbo off, against roughly 4.5 GHz here, so local timings underweight computation. They also underweighted the cost of mapping the 200 MB input: page faults, page-table set-up and tear-down turned out dearer on the box than copying the bytes, which pread later removed (rows 32 and 33). Local single-thread CPU is the better guide to the box's computation, and it agrees on the order: names 50%, field parsing and aggregates 28%, scan 13%, flattening 8%.

Lessons:

- Parsing field by field is latency-bound: each field's position depends on the previous one. Bitmasks first, then fields, roughly halved parse cost per byte. Moving the remaining branches out of the separator loop gained less (about 10%).
- With twelve threads the expensive thing is not computing, it is cache lines that move between cores: atomics on lines other cores read, counters next to read-mostly fields, and first touches of shared pages.
- Lockstep rounds and bounded queues both turn one slow or descheduled worker into a stall for everyone. Unsynchronised sharing with atomics is slower per operation but never waits.
- Under a noisy machine only interleaved A/B runs and CPU time told real changes from noise.
- Most of what remains is memory latency, not instructions: three random lines per record (region map, name slot, group bits) and an atomic OR. Prefetching already hides what it can; only a sparser table measurably helped, at a memory cost.
- The box differs from the laptop in what is expensive, not just in speed: with turbo off, its page faults, page-table set-up and tear-down for a 200 MB mapping cost more than copying the same bytes with pread, a difference invisible locally. Probes that strip work out of a correct build, timed on the box itself, found that; local A/B could not.
- Peak memory starts at about 5 MB before `main` runs: the container runtime's own processes are charged to the same cgroup. Our own use is about 7.5 MB (4 MB name table, 3.7 MB pair bitset, 1 MB region map) plus page tables; the pair bitset is near the floor for exact distinct counting, so M moved little.
- The atomic OR on the shared pair bitset looked like the main remaining parallel cost in the profile, but swapping in a racy plain load and store (for timing only) saved just 7% of CPU (A/B 267 vs 248 ms), and dropping the update entirely 249 ms. Owner-private bitsets fed by queues could win at most that, so the shared atomic version stays: it never makes one worker wait for another.
